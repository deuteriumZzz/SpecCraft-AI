# AI-лог: где ИИ ошибся и как это поймали

Код писал ИИ-ассистент (Claude), поэтому здесь его реальные ошибки в этой работе и то, чем они
были найдены. Реальных ответов Gemini в этом логе пока нет: прогон `--live` ещё не делался.
Ошибки модели при живых запусках нужно дописывать сюда по факту.

| # | Что пошло не так | Как поймали | Что сделано |
| --- | --- | --- | --- |
| 1 | Очистка вывода сначала искала «сайты», потом e-mail: из `a@b.com` удалялось `b.com`, а `a@` оставалось | unit-тест `test_strip_unsafe_removes_links_mail_phone_html` | e-mail проверяется до URL |
| 2 | URL, который есть во входных данных, не сохранялся: точка в конце предложения считалась частью адреса | unit-тест на сохранение адреса из источника | знаки конца предложения отделяются от адреса перед сверкой |
| 3 | Дыра в верификаторе: число из самой инъекции («класс точности 0.1») лежит во входе, поэтому проверка «число есть во входных данных» его пропускала | замечено при разработке evals, воспроизведено тестом | описание с найденной инъекцией не считается доверенным источником чисел, ссылок и извлечённых характеристик |
| 4 | Первое исправление п.3 работало на уровне предложений и ломалось о «см. http://…» (точка после сокращения) | тот же тест `test_numbers_and_links_from_injected_sentence_are_not_trusted` | выбрано консервативное правило: весь `description` недоверенный, менеджер видит предупреждение |
| 5 | Массовая автозамена названий в тестовых данных изменила только ожидаемое значение в тесте, а входную строку с невидимыми символами не тронула | прогон тестов после замены | тест переписан на нейтральных данных |
| 6 | В первоначальном плане предлагалась нормализация NFKC; она бы превращала «м³» в «м3» | разбор до написания кода | использована NFC, NFKC только для поиска инъекций |
| 7 | Для пустого значения (`"питание": ""`) в карточке появлялись две строки «питание: данных нет»: пустая и «ожидаемая» | запуск пайплайна на втором примере (`examples/inputs/thermometer.json`); мой тест не ловил, т.к. сворачивал список в словарь | пустые spec считаются присутствующими, в тест добавлена проверка на отсутствие дублей |
| 8 | **ReDoS.** Регулярка детектора инъекций имела пересекающиеся альтернативы в повторяющейся группе (экспоненциальный перебор), а регулярки очистки вывода были без границ (квадратичный). Замер: 22 повтора слова «все» — 1,5 с, 10 КБ `a-a-…` — 3,8 с | независимое ревью (два субагента), затем мой замер | ограниченные квантификаторы, лимит сканируемого текста, регресс-тест «быстрее 1 с» |
| 9 | Очистка вывода портила технические данные: ряд давлений «0.1 0.25 … МПа» принимался за телефон, а «t < 50 … > 10» за HTML-тег, и текст вырезался | ревью + воспроизведение | телефон только в реальных форматах, тег только с буквой после `<`, одиночный `<b` обезвреживается без удаления текста |
| 10 | Детектор инъекций обходился гомоглифами («игнoрируй» с латинской o), пунктуацией и разбиением фразы между полями; название и производитель всегда считались доверенными | ревью + воспроизведение | сворачивание гомоглифов, проверка полей по отдельности и вместе, недоверенные название/производитель при инъекции |
| 11 | Верификатор не видел числа словами («пять лет»), полноширинные и надстрочные цифры, «0.50» ≠ «0.5» | ревью | NFKC для сравнения, словарь числительных, нормализация хвостовых нулей |
| 12 | Одиночный запрос мог тратить до 9 обращений к Gemini и держать поток до ~4,5 мин; 411/413/500 уходили без заголовков безопасности и без request id; 404/405 не в формате ошибок | ревью | общий бюджет времени, 2 попытки сервиса, единый путь `finish()` для всех ответов, обработчик HTTPException |
| 13 | `check_repo.sh` пропускал `Схема.pdf`: git квотирует не-ASCII имена, и проверка по расширению не срабатывала | ревью (проверено на файле) | чтение имён через `-z`, расширенный список запретов, поиск секретов в индексе; тест на реальном git-репозитории |
| 14 | Моя правка телефона (п.9) оказалась слишком широкой: ветка «+цифры» вырезала температурные диапазоны «+20 -10 0.5 1.0 бар» и обрезала хвост предложения | второе независимое ревью (воспроизведено) | телефон только в формате «код + 2–4 группы с одним разделителем» и не менее 10 цифр; регресс-тесты |
| 15 | «Извлечённая из описания» характеристика принималась по подстроке («25» внутри «1250 мбар»), её название не проходило проверку чисел: «Максимальное давление 250 бар (из описания) = 25» без предупреждения. Предупреждения самой модели не проверялись вовсе | поиск «тихих» сбоев (воспроизведено) | значение как отдельный токен, число-проверка названия, отклонённые считаются и попадают в warnings, предупреждения модели проверяются |
| 16 | Защита от выдуманных чисел тестировалась только для описания: мутации «убрать проверку в заголовке / запросах / commercial / очистку заголовка» выживали (8 из 15) | анализ тестов мутациями | параметризованные тесты на каждое поле модели, e2e-тест через HTTP, evals расширены до 28 кейсов; после правки те же мутации убиваются |
| 17 | Моё первое усиление теста дубликатов тоже пропускало мутацию: сравнивались точные имена, а лишняя строка называлась «… (из описания)» | повторный прогон мутации | тест проверяет все строки с общим началом имени |
| 18 | Узкие подсказки ожидаемых характеристик: «предел допускаемой погрешности» считался диапазоном измерений, «диаметр корпуса» типом корпуса, поле не помечалось как отсутствующее | ревью «тихих» сбоев | подсказки сужены, добавлены тесты на соседние параметры и на значения-заглушки |
| 19 | Интерфейс оставлял на экране карточку прошлого товара с включённой кнопкой «Копировать» после неудачного запроса | ревью | результат сбрасывается в начале запроса, ответ 200 без поля `seo_title` считается ошибкой |
| 20 | Статика отдавалась без `Cache-Control`: браузер по эвристике (Last-Modified) держал старый `tailwind.css`, и после правки разметки страница рисовалась без стилей | при ручной проверке интерфейса в браузере; тот же пункт был в production-аудите | `Cache-Control: no-cache` для статики (перепроверка по ETag), тест на заголовки |
| 21 | Первая версия карточки склоняла счётчики неверно («3 пробелов», «1 предупреждений»), подпись второй шкалы переносилась и ломала ряд, а поле ввода растягивалось на всю высоту длинной карточки | просмотр интерфейса в светлой, тёмной темах и на ширине телефона | функция склонения, короткие подписи шкал, закреплённая левая панель |
| 22 | Панель с классом `flex` оставалась на экране, хотя у неё был атрибут `hidden`: в режиме JSON под полем ввода одновременно торчала пустая форма, а в режиме формы наоборот. Проверка свойств в скрипте этого не показала | реальный скриншот в Chrome (Lighthouse тоже не заметил) | глобальное правило `[hidden] { display: none !important }` |
| 23 | Моя функция `scrollTo` перекрыла встроенный `window.scrollTo`; список `<dl>` содержал недопустимые `span`; фокус-рамка охватывала всю панель результата; подпись «Черновик изменён» пропадала при смене вкладки; запоздалый ответ пересборки мог вернуть правленый текст после сброса | сообщение об ошибке при ручной проверке, Lighthouse (97 → 100), скриншоты, разбор гонки | переименование, выноски псевдоэлементом, панель без рамки, флаг `edited`, отмена устаревших ответов |

Вывод: самые опасные ошибки были не в синтаксисе, а в логике доверия (п.3–4). Поэтому для
каждой такой защиты есть тест и кейс в `evals/cases.yaml`.
